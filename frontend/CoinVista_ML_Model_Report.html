1. Introduction & Theoretical Background

Predicting financial time series is a difficult problem because asset prices exhibit non-stationary, non-linear, and chaotic behavior. Standard linear models (like AutoRegressive Integrated Moving Average - ARIMA) assume linear relationships and constant variance, rendering them ineffective at predicting abrupt trend reversals or learning complex temporal patterns.

To capture these features, CoinVista uses a **Long Short-Term Memory (LSTM)** neural network, which is a type of Recurrent Neural Network (RNN) specifically designed to solve the vanishing gradient problem. While standard RNNs suffer from exponential gradient decay over long sequences, LSTMs maintain a constant error gradient flow through dedicated memory cells and gating systems.

2. Mathematical Mechanics of the LSTM Cell

An LSTM cell controls the flow of information using three mathematical gates: the **Forget Gate**, **Input Gate**, and **Output Gate**. At each time step t, with input vector x_t, hidden state h_{t-1}, and cell state C_{t-1}, the internal gate equations are computed as follows:

2.1. The Forget Gate (f_t)

Determines what percentage of the previous cell state C_{t-1} should be discarded. It applies a sigmoid function ($\sigma$) mapping output values between 0 (completely forget) and 1 (completely retain):

f_t = sigmoid( W_f * [h_{t-1}, x_t] + b_f )

2.2. The Input Gate (i_t) & Candidate Cell State (C~_t)

Determines what new information will be stored in the cell state. The input gate i_t decides which values to update, while C~_t creates a vector of new candidate values using a hyperbolic tangent (tanh) activation function:

i_t = sigmoid( W_i * [h_{t-1}, x_t] + b_i )
C~_t = tanh( W_c * [h_{t-1}, x_t] + b_c )

2.3. Updating the Cell State (C_t)

We update the old cell state C_{t-1} into the new cell state C_t by multiplying the old state by the forget gate f_t, and adding the candidate state C~_t scaled by the input gate i_t:

C_t = f_t * C_{t-1} + i_t * C~_t

2.4. The Output Gate (o_t) & Hidden State (h_t)

The output gate decides what the next hidden state should be. The hidden state is computed by passing the updated cell state C_t through a tanh function and multiplying it by the output gate o_t:

o_t = sigmoid( W_o * [h_{t-1}, x_t] + b_o )
h_t = o_t * tanh(C_t)

3. The TensorFlow.js Model Architecture

The network structure is configured as a sequential model consisting of a recurrent hidden layer and a dense output layer: 

const LOOKBACK = 14; // Input sequence length
const HORIZON  = 7;  // Output prediction sequence length

function buildModel() {
  const m = tf.sequential();
  
  // LSTM Layer: 20 hidden memory units. Input shape is [14, 1] (14 days lookback, 1 feature: price)
  m.add(tf.layers.lstm({ 
    units: 20, 
    inputShape: [LOOKBACK, 1], 
    returnSequences: false 
  }));
  
  // Dense Output Layer: Maps the 20 LSTM unit states to a single predicted price value
  m.add(tf.layers.dense({ units: 1 }));
  
  m.compile({ 
    optimizer: tf.train.adam(0.005), 
    loss: 'meanSquaredError' 
  });
  return m;
}

4. Detailed Data Pipeline Walkthrough

To train the network, the dataset must pass through a strict preparation pipeline:

  1. Min-Max Normalization: Raw asset prices are normalized to scale values between 0 and 1:
    x_norm = (x - min) / (max - min)
    This ensures that weight updates are uniform and stable.
  2. Sequence Generation (Lookback Windows): Historical data is formatted into sliding input-output pairs. With a 14-day lookback, input sequence 1 contains days 1–14, and target 1 is the price of day 15. Sequence 2 contains days 2–15, targeting day 16, and so on.
  3. Tensor Conversion: JavaScript arrays are converted to multidimensional WebGL tensors:
    • Inputs (X) → converted to a 3D tensor of shape [BatchSize, 14, 1].
    • Targets (y) → converted to a 2D tensor of shape [BatchSize, 1].
  4. Autoregressive Multi-Step Forecast: To forecast 7 days ahead, the model runs a loop:
    • Predicts price for day 15 using days 1–14.
    • Appends the predicted price of day 15 to the input window and drops the price of day 1, forming a new input sequence (days 2–15).
    • Predicts day 16, and repeats this process for 7 iterations.

6. Mentor Defense Q&A: Core Technical Questions

Q1: Why did you choose client-side TensorFlow.js instead of a Python-based server (like PyTorch or TensorFlow on Flask/FastAPI)?

Answer: 1. **Infinite Scaling & Zero Server Costs:** Training models in Python requires servers equipped with GPUs or high-end CPUs. Running client-side delegates all computations to the user's browser, eliminating hosting fees. 2. **Privacy:** User datasets and historical selections remain local to the browser. 3. **Low Latency:** Eliminates the network overhead of sending pricing data back and forth to an external API.

Q2: Explain how a Web Worker prevents the browser interface from freezing.

Answer: JavaScript is single-threaded and shares its execution thread with layout drawing, user interaction, and rendering. Training a neural network requires intensive matrix multiplication. Running it on the main thread stops layout rendering, causing the browser to freeze. A Web Worker runs on a separate operating system thread. We load TensorFlow.js inside this worker so that the main thread remains free to handle page interactions and animations.

Q3: Why is Min-Max normalization necessary for LSTMs? What happens if you skip it?

Answer: LSTMs use activation functions like sigmoid and tanh. If raw prices (e.g., Bitcoin at $60,000) are fed directly into the model, the inputs will fall into the flat saturation regions of these activation functions where the derivative is near zero. This leads to vanishing gradients, meaning weights stop updating and the model fails to learn. Normalizing the data to a [0, 1] range ensures inputs align with the active regions of the activation functions, leading to stable gradient flow.

Q4: How does the autoregressive forecasting loop work? Why not just configure the Dense output layer to return 7 values directly?

Answer: Returning 7 values directly from a Dense layer is a multi-step direct forecast. It assumes independent relationships between the forecasted days. An autoregressive loop (feeding the prediction of day 1 back as input for day 2) maintains the sequential dependency of time-series data, allowing the model to project trends where day 16 naturally builds on the predicted value of day 15.

Q5: Explain how the Adam optimizer works. What is the significance of the 0.005 learning rate?

Answer: **Adam** (Adaptive Moment Estimation) maintains running averages of both the gradients (first moment) and the squared gradients (second moment). It scales the learning rate dynamically for each parameter. The learning rate of 0.005 controls the step size taken during gradient descent. A learning rate that is too high causes the model to oscillate and overshoot the global minimum, while a rate that is too low causes training to stall. 0.005 balances speed and convergence stability for this dataset.

Q6: What is a tensor memory leak in TensorFlow.js, and how is it prevented in your code?

Answer: TensorFlow.js uses WebGL to run calculations on the GPU. Because JavaScript's garbage collector only manages CPU heap memory, it cannot automatically release GPU memory allocated by tensors. Unreleased tensors remain on the GPU, causing memory usage to grow until the browser tab crashes. We prevent this by calling tensor.dispose() on all intermediate tensors immediately after use, ensuring GPU memory is released.

Q7: Why did you limit the model to a 14-day lookback and 20 LSTM hidden units?

Answer: Financial time series data is highly noisy. Complex models with many units or long lookback windows tend to overfit, memorizing noise rather than learning generalizable trends. Keeping the network small (20 hidden units and 14-day lookback) acts as a form of regularization, helping the model learn broad trends instead of overfitting to noisy fluctuations.

Q8: How did you calculate the standard deviation bands shown on the forecast chart?

Answer: We calculate the standard deviation of the last 14 days of historical prices relative to the final closing price: `std = sqrt( sum( (price_i - last_price)^2 ) / N )`. This value represents recent market volatility. We then plot `Forecast + std` and `Forecast - std` to show the confidence interval.

Q9: What are the main limitations of this prediction system?

Answer: LSTMs predict future values based solely on historical price patterns. They cannot account for external variables like market news, policy changes, or sudden order-book liquidations. Therefore, it is presented as a technical analysis tool, not financial advice.

Q10: Why did you compile the Web Worker code from a Blob string inside the same file?

Answer: Traditional Web Workers require a separate physical file on the server. If the application is opened locally via the `file://` protocol, browsers block separate worker files due to same-origin security policies. By compiling the worker from a string blob (Blob) and generating a local object URL (URL.createObjectURL(blob)), the application can run in any browser environment without CORS configuration blocks.
